# QB-05 — Data Tables

**State:** DESIGN DRAFT · no implementation signoff
**Application/profile:** QueryBridge, existing web schema/data tooling
**Design:** https://www.figma.com/design/EDqSijN3CkN06Q06ZM9hI5?node-id=2-215 (editable Figma frame)
**Route:** /admin/data-tables
**Standard:** Application-Standard v1.0, adopted in `STANDARD_VERSION.md`.

## Goal / actors / permissions
Review and edit permitted local dataset records. User: schema analyst or authorised administrator depending on function. Preserve current route permissions, read-only vs editable controls, audit and export restrictions. Never expose an unauthorised edit action.

## Data and page hierarchy
Target table, selected row, edit permission and audit. Desktop: shared top nav, breadcrumb/title/action, filter and metadata controls, primary work area, optional right detail/inspector, status and provenance. Application fields must not imply a real UI screen control unless recorded. Do not invent JOINs or lineage.

## Main interactions
Filter rows; select row; edit authorised fields; validate/save; cancel. Include visible primary action and keyboard equivalent; accessible labels and focus rings for icon controls. Specialised diagram/canvas requires tabular or descriptive accessible alternative.

## Responsive / theme
- Wide desktop **1440px**: compare draft frame with approved working screen.
- Laptop **1280px**: preserve primary actions and allow dense tables to scroll within own region.
- Compact/tablet **1024/768px**: collapse secondary panel and use controlled column visibility.
- Mobile **390px**: one-column task-first controls and list/detail navigation. Draft mobile frame available for QB-02, QB-03 and QB-04; other mobile frames pending.
- At **200% zoom**: no clipped controls or hidden save/export action.
- Both light and dark modes use shared semantic tokens; current Figma palette is **draft**, not official branding.

## States and accessibility
Define loading, success, empty, stale, invalid, no_permission, not_configured, saved/unsaved, export success/failure and retry where relevant. Distinguish zero records from data not configured. Aim for WCAG 2.2 AA and test keyboard/pointer/touch. Mockup currently covers default state only; full state matrix pending.
